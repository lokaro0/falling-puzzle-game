# GUI版の基本設計と実装タスク

## 構成と役割

- ncurses版とraylib版を別の実行ファイルにし、domainとstorageを共有する。
- GUIの入口は`src/gui_main.cpp`。まず関数と列挙型で構成し、責務が増えた時点でファイルを分ける。
- 毎フレーム、入力 → 更新 → 描画を行う。画面の状態とプレイ進行の状態を分ける。
- 最初は800×640のウィンドウ、図形、標準フォントを使う。正式な見た目は後で調整する。
- raylibの各関数と設計の意図を理解しながら、小さな単位で実装・動作確認を進める。

## 画面と遷移

| 状態 | 表示・遷移 |
| --- | --- |
| Title | 大きなタイトルの下にStart / High Score / Tutorial / Quitを縦に並べる。Start → Playing、各項目 → 対応する仮画面、Quit → 終了。 |
| HighScore / Tutorial | 当面は同じウィンドウ内の仮画面。Esc → Title。それ以外のキーでEscで戻れることを案内する。 |
| Playing | 従来の盤面、操作中ピース、Next、Score、High Score。出現不能 → GameOver。 |
| GameOver | プレイ画面中央にGAME OVERを演出表示。新しいキー入力 → Result。演出途中もスキップ可能。 |
| Result | Score、High Score、Retry、Title。Retry → 新しいPlaying、Title → Title。Max Chainは連鎖実装後に追加。 |

メニューは↑↓・W/Sで移動、Enterで決定する。画面遷移に使った入力を次画面へ持ち越さない。マウスは保留。タイトルの最高得点表示は要件に従い維持し、専用High Score画面の実データ表示は後回しにする。

raylib標準のEsc終了は無効にし、プレイ中のEsc・×で終了確認を開く。↑↓・W/SでYes / Noを選び、Enterで決定する。初期選択はNoとし、Escでも再開できる。確認中はゲーム更新を止める。

## プレイ進行

GUI側が状態・タイマー・演出対象を保持し、domain側が盤面の変更と判定を担当する。

`操作中 → 固定 → 重力 → 消去判定 → 消去演出 → 消去 → 重力 → 再判定 → 次ピース`

- 消去対象がなければ次ピースへ進む。消去・重力中はピース操作を受け付けず、終了操作には応答する。
- 経過秒数で進め、各段階と次ピースの開始時に対応するタイマーをリセットする。演出のための長い待機処理を置かない。
- `resolve()`はncurses版と既存テスト向けに維持する。GUI版では`erase_once()`と`apply_gravity_one_row()`を呼び、消去と重力を段階的に進める。消去前の演出は今後追加する。
- RetryではGame、Next、演出データ、タイマーを初期化し、High Scoreを保持する。

## ビルド設定

`BUILD_NCURSES`は既定でON、`BUILD_GUI`はOFF。GUIのみを構成する場合は次を指定する。

```powershell
cmake -S <source> -B <build> -G "MinGW Makefiles" -DBUILD_NCURSES=OFF -DBUILD_GUI=ON -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Release
cmake --build <build> --parallel 4
ctest --test-dir <build> --output-on-failure
```

GUI版のエントリーポイントは`src/gui_main.cpp`とする。raylibは5.5のコミット`c1ab645ca298a2801097931d1079b10ff7eb9df8`に固定し、CMakeのFetchContentで取得する。
