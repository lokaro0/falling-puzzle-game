# ADR-001: GUIライブラリにraylibを採用する

- 状態：採用
- 決定日：2026-10-20

## 背景

既存のC++17のゲームロジックを再利用し、Windows向けの2D GUI版を作る。描画、入力、音声を扱えるraylibとSDL3で小さな試作を作成した。

## 検証結果と選択肢

| 候補 | 確認結果 |
| --- | --- |
| raylib 5.5 | Releaseビルド、既存ロジックの3テスト、起動・描画・音声初期化に成功。入力・回転・リセット・音・終了を手動確認した。 |
| SDL3 3.4.18 | Releaseビルド、既存ロジックの3テスト、起動・描画・音声初期化に成功。入力・回転・リセット・音・終了を手動確認した。 |

両者で今回の基本機能を実装できる見込みが得られた。試作コードを比較し、raylibのAPIが今回の処理を簡潔に表現でき、入力・更新・描画の流れを追いやすかったため採用した。既存のdomain層を再利用しながら、画面遷移やゲーム進行の実装を進める方針に適していると判断した。

## 決定

GUI版の描画、入力、音声にraylibを採用する。domain層はraylibへ依存させない。

性能の優劣や保守性の定量比較は行っておらず、それらを採用理由にはしない。依存バージョンは試作で使用したraylib 5.5のコミット`c1ab645ca298a2801097931d1079b10ff7eb9df8`に固定し、CMakeのFetchContentで取得する。

## 影響と導入後の状況

- 描画・入力・音声を少ないAPIで実装でき、ゲーム進行の設計と完成に集中しやすい。
- 日本語パスを含むMinGWビルドで問題が出たため、英数字のパスで構築する手順を採用した。
- domain層をraylibへ依存させず、GUI版の画面遷移とゲーム進行を実装した。
- Releaseビルドと既存4テストを確認し、実行ファイルと必要なDLLを同梱した配布物を作成した。
- raylib付属コードのコンパイル警告への対応、日本語フォント、Webビルドは今後の検討事項とする。
