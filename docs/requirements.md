# Falling Puzzle Game GUI版 要件定義

## 目的

本書は、[開発計画](project-plan.md)で定めた最初の正式版について、実装と受け入れ確認に必要な要件を定義する。既存仕様の詳細は[アーキテクチャ資料](architecture.md)と[リファクタリング記録](refactoring-plan.md)を参照する。

以下は延期項目を含む完成形の要件。11/7までの実装優先順位と仮画面の扱いは[基本設計と実装タスク](gui-implementation.md)に従う。

## 機能要件

### FR-01 タイトル画面

起動時にタイトル画面を表示する。

**受け入れ条件**

- 大きなタイトルの下にStart、High Score、Tutorial、Quitを縦に並べる
- ↑↓・W/Sで選択し、Enterで決定できる（マウス対応は保留）
- 保存済みのHigh Scoreを確認できる
- Startで新しいゲームを開始する
- Quitまたはウィンドウの閉じる操作で正常終了する。プレイ中はEsc・Qで即終了せず、誤終了を防ぐ

### FR-02 チュートリアル

タイトル画面からチュートリアルを選択し、基本操作とルールを確認できる。

当面はHigh ScoreとTutorialを同じウィンドウ内の仮画面とする。EscでTitleへ戻り、それ以外のキーではEscで戻れることを案内する。

**受け入れ条件**

- 移動、落下、回転の操作を確認できる
- 正式なTutorialでは説明文を表示しながら実際に操作できる
- 「同色4個以上で消去」という条件を確認できる
- チュートリアルからタイトル画面へ戻れる

### FR-03 ゲームプレイ

ncurses版の基本操作とゲーム規則を維持してGUIへ移行する。

**受け入れ条件**

- 盤面、操作中のブロック、Next、Score、High Scoreを表示する
- 既存のdomain層の自動テストが成功する
- 意図的に変更する連鎖、得点、演出以外の基本動作がncurses版と一致する

### FR-04 ゲーム進行

消去と重力の演出を、ウィンドウのイベント処理を止めずに進行する。

**受け入れ条件**

- 消去対象と重力による落下の途中経過を表示する
- 同じ消去段階の対象を同時消去として扱う
- 演出中もウィンドウを閉じる操作へ応答する

### FR-05 連鎖

消去と重力の繰り返し回数を連鎖段数とし、同時に消えたグループ数とは区別する。

**受け入れ条件**

- 最初の消去を1連鎖とする
- 同じ段階で複数グループが消えても連鎖段数は1だけ増える
- 重力後の追加消去を次の連鎖として数える
- 一連の消去後に現在の連鎖数をリセットし、プレイ中の最大連鎖数は保持する

### FR-06 得点

消去個数と連鎖段数に基づいて得点を計算する。

**受け入れ条件**

- 連鎖後半ほど、同じ消去個数でも高得点になる
- 段階ごとの加点と合計得点を画面なしで自動テストできる
- 計算式と倍率表を実装前に本書へ追記する

### FR-07 Game Overと結果画面

Game Overをプレイヤーへ明確に伝えた後、結果画面へ移行する。

**受け入れ条件**

- Game Over時に、プレイ画面の中央へ`GAME OVER`を演出付きで表示する
- 表示完了後の新たな任意のキー入力で結果画面へ移行する
- 結果画面に最終Score、High Score、Max Chainを表示する
- High Score更新時は、そのことを表示する
- Retryでプレイ状態を初期化して新しいゲームを開始する
- Titleでタイトル画面へ戻る
- Retry後も保存済みのHigh Scoreは維持する

### FR-08 ハイスコア保存

High Scoreをゲーム終了後も保持する。

**受け入れ条件**

- 新しいScoreが保存済みHigh Scoreを超えた場合だけ更新する
- 次回起動時に読み込み、タイトル画面とプレイ画面へ表示する
- 保存データがなくても起動でき、配布先で書き込み可能な場所へ保存する

### FR-09 演出と効果音

着地、消去、連鎖、Game Overを画面表示または効果音で識別できる。

**受け入れ条件**

- 消去前に対象へ視覚的な変化を与える
- 現在の連鎖段数を画面へ表示する
- 着地、消去、連鎖、Game Overに対応する効果音を再生する
- 連鎖が進んだことを音または表示の変化から判別できる

## 非機能要件

### NFR-01 対応環境と配布

- Windows 11を正式な動作対象とする
- 開発環境のないPCで、必要なライブラリとアセットを含む配布物から起動できる

### NFR-02 保守性

- domain層をGUIライブラリ、音声、ファイル保存へ直接依存させない
- ncurses版とGUI版でdomain層を共有し、ncursesなしでもGUI版とテストを構成できる

### NFR-03 品質確認

- 既存テストを維持し、連鎖、得点、Retryの自動テストを追加する
- タイトルからRetryまでを手動確認する
- CIでビルドと自動テストを実行する
- Releaseビルドを別のWindows PCで起動確認する

### NFR-04 操作性

- 口頭説明なしでゲームを開始し、Game Over後の次の操作を判断できる
- 5人以上のユーザーテストで迷った箇所を記録し、重要な問題を修正する

### NFR-05 素材

- 第三者の画像、フォント、音声は利用条件を確認し、必要な出典とライセンスを記載する

## 基本機能の完成後に検討する要件

- FR-10 Webブラウザからのプレイ
- FR-11 オンラインランキングへのScore登録と閲覧

## 未決定事項

- 得点計算式、連鎖倍率、大量消去ボーナス
- 画面サイズとレイアウト
- Game Over演出の具体的な動きと長さ
- 使用する画像、フォント、効果音
- High Scoreの保存場所と保存形式

GUIライブラリはraylibを採用する。理由と検証結果は[選定記録](decisions/001-gui-library.md)を参照する。

該当機能の実装前に決定し、本書またはADRを更新する。
