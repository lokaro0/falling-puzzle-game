# アーキテクチャ

## 概要

本プロジェクトは、ぷよぷよ風の落下パズルゲームを C++ と ncurses で実装したものである。

初版ではゲームルール、キー入力、ncurses による描画、ハイスコアのファイル保存が `src/puyo.cpp` に集約されていた。改善版では、それぞれの責務を分離し、ゲームルールを画面なしでテストできる構成にした。

## 層構造

```text
main
├─ domain   : ゲーム規則と状態
├─ ui       : ncursesによる入力と描画
└─ storage  : ハイスコアのファイル保存
```

依存関係は次の方向に限定する。

```text
main ──→ domain
  ├────→ ui ──→ domain
  └────→ storage

tests ──→ domain
      └─→ storage
```

`domain` は UI やファイル保存を参照しない。そのため、端末画面を開かずにゲーム規則をテストできる。

## 各層の責務

### domain

`src/domain/` はゲームの状態とルールを担当する。

| 型 | 責務 |
| --- | --- |
| `Color` | ぷよの色を表す |
| `Position` | 盤面上の行・列を表す |
| `Board` | 固定済みぷよの配置を保持する |
| `Piece` | 操作中の2個組ぷよを表す |
| `Game` | 移動、回転、固定、消去、重力、得点、ゲームオーバーを管理する |

`Board` は `std::vector<Color>` を使ってセルを保持する。手動のメモリ管理を避け、盤面操作とゲーム規則に集中できるようにした。

`Game` は ncurses やファイル操作を含まない。操作の可否や消去結果は、ゲーム状態だけから決定される。

### ui

`src/ui/` は ncurses を使った端末入出力を担当する。

| 型 | 責務 |
| --- | --- |
| `NcursesSession` | ncurses の初期化と終了 |
| `NcursesInput` | キー入力をゲーム操作へ変換 |
| `NcursesRenderer` | `Game` の盤面・スコア・ハイスコアを描画 |

`NcursesSession` は RAII を利用する。オブジェクトの生成時に ncurses を初期化し、破棄時に `endwin()` を呼ぶことで、通常終了時だけでなく例外発生時にも端末状態を戻せる。

### storage

`src/storage/` はハイスコアの保存を担当する。

| 型 | 責務 |
| --- | --- |
| `HighScoreStore` | ハイスコアファイルの読み込みと保存 |

`HighScoreStore` はゲーム規則を知らず、指定されたパスに整数のスコアを保存するだけである。ファイルが存在しない場合や内容が不正な場合は、初期値 `0` として扱う。

### main

`src/main.cpp` はアプリケーション全体を組み立てる。

```text
入力を読む
↓
Game を更新する
↓
必要ならスコアを保存する
↓
Game の状態を描画する
↓
短時間待機して繰り返す
```

自然落下の時間管理やランダムなぷよ生成は `main` が担当する。一方で、移動できるか、消去できるか、重力でどこまで落ちるかは `Game` が担当する。

## 主な設計判断

### ゲーム規則と ncurses を分離した

ゲーム規則が ncurses に依存すると、画面表示を伴わない検証が難しくなる。そこで `Game` は `Board` と `Piece` だけを使い、入力や描画は UI 層に分離した。

この結果、消去や重力のようなルールを CTest で自動検証できる。

### 独自コンテナではなく `std::vector` を使う

初版には独自の `vector` / `matrix` があった。改善版では `std::vector` を用い、メモリ確保・解放・コピー・移動を標準ライブラリへ任せた。

独自コンテナを実装すること自体は学習になるが、ゲーム本体で必要なのは盤面操作とゲーム規則である。既存の標準コンテナを使うことで、実装量と不具合の可能性を抑えた。

### ハイスコアをゲーム規則から分離した

ハイスコア保存はゲーム規則ではなく、ファイルI/Oの関心事である。そのため `HighScoreStore` として分離した。

これにより、将来ファイル保存を別の方式へ変更しても、`Game` のルールを変更せずに済む。

### 2個組を固定した後に重力を適用する

2個組の片方だけが障害物に接した場合、もう片方が空中に残らないよう、固定後に盤面全体へ重力を適用する。

```text
2個組を固定
↓
盤面全体へ重力を適用
↓
消去判定・連鎖処理
```

この方式により、2個組の表現を複雑化せず、片方だけが接地した状況を扱える。

## テスト方針

テストは UI を含めず、再現可能なゲーム規則と保存処理を対象にする。

- `Board`：盤面の境界、初期化、コピー
- `Piece`：移動、回転、相方ぷよの座標
- `Game`：衝突、固定、消去、重力、連鎖、ゲームオーバー
- `HighScoreStore`：ファイルがない場合、保存と読み戻し、不正な内容

ncurses の画面表示とキー入力は、ビルド後に手動で確認する。
